# Head-camera perception

The head model reuses the wrist perception VLM backbone, text conditioning,
heatmap/offset head, visibility, depth, and wall-normal losses. The only input
camera is the current `ego_view` image. State and action remain ignored by the
model, as in wrist perception.

The dataset must contain `heatmap_labels_head/`, generated by
`dataset_tools.heatmap_labels.process_head_dataset` in `humanoid-mrl`. Its frame
indices are a temporally thinned subset of the balanced wrist sidecar, but all
labels are in the head optical frame. Both sidecars can coexist. The selected
sidecar controls sparse sampling, label joins, and `NUM_EPOCHS` step counts.

After syncing the updated code and dataset to Euler, from `~/groot`:

```bash
sbatch submit_head_perception_euler.sh
```

This thin wrapper shares `submit_perception_euler.sh` and defaults to:

- Dataset: `/cluster/work/mrl/$USER/datasets/g1_dataset_autocollect_v2_rightfreq`
- Run: `head_perception_v1`
- Labels: `heatmap_labels_head`
- Modality config: `register_head_perception_modality.py`
- Image target/crop: 480/432 (native head resolution; same 0.9 zoom augmentation)

The wrist script's overrides still apply, for example `RUN_NAME`,
`BASE_MODEL_PATH`, `NUM_EPOCHS`, `MAX_STEPS`, and loss weights. Its default batch,
optimizer and training length are unchanged. This script submits a separate head
model; it does not replace a wrist checkpoint or modify the robot planner.

For an existing local training container, select the same setup explicitly:

```bash
PERCEPTION_CAMERA=head DATASET_DIR=/path/to/g1_dataset_autocollect_v2_rightfreq \
    bash setup_and_train_perception.sh
```

Inference uses the existing `run_perception_server.py` and `PerceptionPolicy`.
The saved processor config selects `video.ego_view`; clients must supply that
image key. Output pixels, depth and wall normals refer to the head camera.
